# Terminal WebSocket v1

本文件描述当前实现，不是功能愿景。端点为 `/ws/terminals/{terminalID}?offset=<十进制字节偏移>`。

## 权限

握手需要有效的浏览器会话 Cookie、完全匹配的 Host 与允许的 Origin；URL 不携带认证令牌。终端属于创建它的登录会话。每个终端只允许一个写入连接，不会自动抢占别的窗口。

## 帧

| 方向 | 类型 | 内容 |
| --- | --- | --- |
| 服务端 → 浏览器 | 二进制 | `0x01` + 8 字节 unsigned big-endian **起始字节偏移** + 1–32768 字节原始终端输出 |
| 浏览器 → 服务端 | 二进制 | `0x02` + 1–32768 字节输入；普通文本只 UTF-8 编码一次，xterm `onBinary` 按字节映射 |
| 服务端 → 浏览器 | JSON 文本 | `{"type":"hello","version":1,"offset":"0"}` |
| 浏览器 → 服务端 | JSON 文本 | `{"type":"ack","offset":"<已解析字节末尾>"}` |
| 浏览器 → 服务端 | JSON 文本 | `{"type":"resize","rows":28,"cols":100}` |
| 服务端 → 浏览器 | JSON 文本 | `{"type":"state","status":"exited","exitCode":0}`；status 可能为 exited、disconnected 或 closed。远端报告退出码时带 `exitCode`（0–255），被信号终止时带 `exitSignal`（如 `TERM`），连接丢失而无退出信息时两者都省略 |

偏移是原始输出 payload 的累计字节数，不包括 9 字节 envelope，不是字符数。JSON 中使用十进制字符串，浏览器使用 BigInt。UTF-8 字符及 ANSI 序列允许跨帧，交给同一个 xterm 解析器持续处理，不按消息独立解码。

## 流控与重连

- ACK 只能在 `xterm.write` 完成解析的回调中发送；服务端拒绝回退或超过发送水位的 ACK。
- 每个连接最多 256 KiB 未确认数据；每个终端最多 8 MiB 未确认缓存，全局最多 8 个终端（含正在拨号的名额）。满时阻塞上游读取，不丢弃旧数据来伪造连续输出。
- WebSocket 断开后保留终端 60 秒。同一页面等待已排队解析的输出完成，再以已应用 offset 重连；不重放键盘输入。
- 整页刷新不恢复 xterm 解析器状态，不用新建窗口从环形缓存中间假装恢复 Vim/tmux。界面显示旧会话清理入口；保留期届满后关闭。
- 已丢弃的 offset、未来 offset、其他登录的 terminalID、重复附着均拒绝。返回 HTTP 错误时浏览器可能只得到通用的 WebSocket 失败，不把它误称为 SSH 已重建。
- 15 秒发送一次 ping，5 秒无 pong 结束浏览器通道；SSH 另有 keepalive 与输入写入超时。
- 锁定/注销/过期会取消在途请求并结束该登录会话的终端。应用退出回收所有会话。

## 输入与副作用

快捷键在 IME composition 时让行。浏览器中超过 1 MiB 的单次输入/待发送队列不接受；断线时不缓存新命令。多行粘贴确认后使用 xterm 的 paste 路径。OSC 52 不自动写剪贴板；外链只允许 HTTP/HTTPS，隔离 opener。

OSC 7 只提供远端目录**候选提示**：校验 file URI、主机与路径，排除认证信息、查询、fragment 与 NUL。不会将它解释成本机路径。上传仍需要确认明确目录。

## 命令片段与广播

片段“插入/执行”和多主机广播都由浏览器通过**各终端自己的这条写入连接**发送一次 `0x02` 输入帧，不新增服务端写入通道，也不绕过“一终端一写入方”。广播逐个目标发送整条命令（不是逐键），只报告“已发送 / 未发送（连接未就绪）”；不会排队、重试或在重连后补发。应用无法判断远端 shell 是否处于提示符、密码输入或全屏程序中，这由用户在预览中确认。
