# v0.3.x 交接与架构备忘

本文档记录 `0.2.0-beta.1` 之后截至 **`v0.3.1`** 的改动、关键模块位置、发布链路以及已踩过的坑，方便后续会话快速定位并修改功能。

## 1. 当前形态与仓库信息

- **公开仓库**：`xxddccaa/ssh-workbench`（默认分支 `main`）
- **CLI 命令与入口**：`sshw` / `sshw.exe`（源码位于 `cmd/sshw/`，Go module 仍为 `sshworkbench`）
- **当前发布版本**：`v0.3.1`（见 `cmd/sshw/main.go` 中的 `var version = "0.3.1"`）
- **一键安装 / 升级**：
  - 安装脚本：`install.sh`（默认从 `https://github.com/xxddccaa/ssh-workbench/releases/latest` 的 302 重定向解析最新 tag，失败再回退 `api.github.com`，避免匿名 API 403 限流；若发现旧版 `sshworkbench` 会自动创建指向 `sshw` 的软链接）
  - 内置命令：`sshw upgrade`（`cmd/sshw/upgrade.go`，同样优先走 `releases/latest` 重定向解析，校验 `SHA256SUMS` 并原子替换自身二进制）

## 2. 核心设计变化（相对 `05-current-implementation.md`）

### 2.1 默认开箱直连（Direct-Open）
- **默认值**：直接运行 `sshw` 或 `sshw --listen 0.0.0.0:7331` 时 `RequireAuth = false`，不启用 bootstrap token、不拦截局域网 / 反代 HTTP `Host` 与 `Origin`、不弹登录页。
- **保留门禁开关**：显式传入 `--auth`（本机一次性 token）或 `--remote`（所有者密码 + HTTPS + 严格校验）时仍保留原有严格模式。
- **关键文件**：
  - `cmd/sshw/main.go`
  - `internal/bootstrap/application.go`
  - `internal/auth/service.go`（`OpenSession()`）
  - `internal/transport/httpapi/server.go`、`internal/transport/httpapi/websocket.go`

### 2.2 本机 `~/.ssh/config` 与 OpenSSH 兼容
- **实时列表与一键直连**：
  - `GET /api/v1/ssh-config/hosts` 直接返回本机解析出的主机候选项，侧边栏 `SSH Config (~/.ssh/config)` 分组与快速启动台单点即可直连。
  - 使用虚拟主机 ID `sshcfg:<alias>`（已在 OpenAPI 中将 `hostId` `maxLength` 提升至 `260`）。
  - 同时支持 **Quick Connect**（无需先保存主机，直接输入 `user@host:port` 连接）。
- **软链接与特殊指令**：
  - `Include` 支持追踪外部软链接目录/文件（如 OrbStack、Colima、dotfiles），同时防循环并限制深度。
  - `ProxyCommand` 已实现解析与进程管道执行（`internal/adapters/sshtransport/proxy.go`），支持 `ProxyJump` 单级跳板。
  - 认证新增 `authMode: "auto"`（`AuthAuto`），按顺序尝试：显式 `IdentityFile`（支持软链接私钥）→ 默认 `~/.ssh/id_ed25519` / `id_ecdsa` / `id_rsa` → `SSH_AUTH_SOCK` agent → 密码 / keyboard-interactive 提示。
  - 未知主机密钥采用 `known_hosts` 匹配 + TOFU 自动信任，密钥变更/不匹配时仍提示或失败关闭。
- **关键文件**：
  - `internal/sshconfig/*`
  - `internal/launch/launch.go`、`internal/hosts/hosts.go`、`internal/imports/imports.go`
  - `internal/adapters/sshtransport/{connector.go,localfiles.go,proxy.go}`
  - `internal/workspaces/workspaces.go`
  - `internal/transport/httpapi/{attempts.go,dto.go,workspace.go}`

### 2.3 界面重构（Termius / Tabby 风格）

## 3. 已解决的工程与跨平台坑（修改时注意保留）

1. **`npm ci` 依赖冲突**：`web/package.json` 使用 `typescript@6.x`，而 `openapi-typescript@7.13.0` 声明 peer 为 `typescript@"^5.x"`，因此在 `web/.npmrc` 保留了 `legacy-peer-deps=true`。
2. **Windows 端口占用错误码**：Go 标准库在 Windows 上 `errors.Is(err, syscall.EADDRINUSE)` 不能匹配 Winsock `10048`，已拆分为 `internal/tunnels/listen_windows.go`（使用 `windows.WSAEADDRINUSE` / `WSAEACCES`）与 `internal/tunnels/listen_unix.go`。
3. **Windows 路径测试**：`filepath.IsAbs("/etc/ssh/...")` 在 Windows 返回 `false`，单元测试需使用带卷标的绝对路径（参见 `internal/sshconfig/sshconfig_test.go` 中的 `TestAuthenticationSettings`）。
4. **GitHub 限流导致下载失败**：`install.sh` 与 `cmd/sshw/upgrade.go` 不再强依赖 `api.github.com`，优先通过 `releases/latest` 的 `302 Location` 提取 tag。
5. **契约与静态资源**：修改 `api/openapi.json` 后必须运行 `make generate`；前端构建产物内嵌进 Go 可执行文件，`make dist` 与 `.github/workflows/release.yml` 会自动执行 `make web notices`。

## 4. 发版与校验常用命令

```sh
make test        # OpenAPI 前后端契约检查 + Go -race/vet + TS + Vitest
make e2e         # Playwright + loopback SSH/SFTP fixture 端到端测试
make build       # 构建内嵌前端的单文件 bin/sshw
make dist        # 交叉编译 darwin/linux/windows 五平台压缩包 + SHA256SUMS
```

发版流程：更新 `cmd/sshw/main.go` 中的 `version`，提交推送 `main` 后打 `vX.Y.Z` 标签推送即可触发 `.github/workflows/release.yml` 自动测试并发布 Release。
